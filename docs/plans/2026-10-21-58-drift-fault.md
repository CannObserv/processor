# Drift alerts carry `metadata.fault`

## Problem

`post_checkin` sends `{"status", "variables"}` only. Since status#28 co-status groups a run of `alert`s into one fault by `metadata.fault`; a change of it reports at once. Without the key a change of drift `kind` inside one fault (`lag` → `off_main`, `unstamped`) waits for the daily reminder, up to ~23.5 h. Same for a `--test-alert` sent while a real fault is open.

## Approach

The sibling contract (status#32, #51; broker#110): every `alert` sends `"metadata": {"fault": <kind>}`; an `ok` sends no `metadata` key at all.

- `checkin.post_checkin` gains `metadata: dict[str, str] | None = None`; the key enters the body only when given. Liveness's call is unchanged (it only checks in `ok`).
- `drift.Verdict.metadata()` beside `variables()`, as broker's: `{"fault": kind}` when `status == "alert"`, else `None`. The fault is the kind token only, never `body` or a URL.
- `__main__._drift` passes `metadata=verdict.metadata()`.
- Docs: `checkin.py`'s module docstring, `drift.py`'s `Verdict`, DEPLOYMENT.md § The drift check (each `alert` names its kind as `metadata.fault`; a `--test-alert` during an open fault reports at once as its own fault, `test`).

## Tests (red first)

- `test_checkin.py`: no `metadata` → exactly today's body (no key); `metadata` given → in the body.
- `test_drift.py::TestVerdict`: every alerting kind's `metadata()` is `{"fault": kind}`; `ok` and `silent` are `None`.
- `test_drift.py::TestTheCommand`: a `lag` check-in carries `metadata.fault == "lag"`; an `ok` has no `metadata` key; `--test-alert`'s carries `"test"`.
- `test_liveness.py`: body already pinned by equality (no `metadata`); unchanged.

# co-core 0.38.0

## Problem

`application/json` falls back to `HtmlExtractor`, so a `jsonpath` spec was refused (since 0.32.0) and a `full_page` one fingerprinted the raw bytes. cannobserv v0.38.0 (`33676e6`) carries:
- **cannobserv#354**: `JsonExtractor` for `application/json`, `application/ld+json`, `application/vnd.api+json` (no `+json` suffix rule); the translator maps `jsonpath` → `{"jsonpath": selector}`; `resolve_dispatch_essence` maps a `.json` path to `application/json`.
- **cannobserv#557**: `xpath` on HTML is honoured.
- **cannobserv#570**: `ignore_selectors` (HTML only); an uncompilable CSS selector raises `UnsupportedExtractionError`.

## The catch-up reading (0.37.0 → 0.38.0, 0.37.1 between)

Checked in code (`git diff v0.37.0 v0.38.0 -- packages/`), not only the CHANGELOG:
- **Contract models** (`changes.py`): `ContentProcessCommand`, `ProcessingCompleteEvent`/`Emit`, `ProcessingFailedEvent`/`Emit`, `ContentProcessCommandEmit`, `ProcessingFailureReason`: identical with docstrings stripped (AST compare). The rest is the capture pair (#571) and `InfoItemPrimaryChangedEvent`'s docstring.
- **Bus**: `envelope.py` registers the capture pair and moves `info_item_primary_changed`'s key to `…:occurred_at` (#578); `streams.py` adds `CONTENT_CAPTURE`. Processor reads neither. `dead_letter`, `exceptions`, `co_core_aio`, `co_core_sync`: version strings only.
- **`canonical_text`, blob store, hashing**: unchanged. **`spec_fingerprint`**: serialization moved into the shared `_canonical_json`, same `json.dumps` arguments, so `spec1:` is unchanged (the goldens' unmoved `spec_fingerprint`s confirm it).
- **Extract**: `json_.py`, `_xpath.py`, `_canonical_json.py` new; `html.py` (xpath, ignore_selectors, the selector refusal); the dispatch map; the translator; `refuse_unhonoured`'s two new keys; `media_type`'s `.json` tiebreak.
- **Dependencies**: the `extract` extra adds `python-jsonpath>=2.2,<3` and declares `soupsieve>=2.0,<3` (already installed via bs4). Sibling floors move to `>=0.38,<0.39`.
- **CHANGELOG** 0.37.1 (bus-only) and 0.38.0: no security entries.

`processors/extract.py` needs no code change. `resolve_dispatch_essence` is the contract, but Processor never calls it: it dispatches whatever essence arrives, so either adoption order is safe, and the bump is notice to Watcher, not coordination (D5).

# shellcheck the shipped shell; CI on the node's image

A port of CannObserv/broker#112 (`scripts/shellcheck.sh`, `.githooks/pre-commit`, `tests/deploy/test_shellcheck_gate.py`), plus broker#88's `runs-on` pin.

**Problem.**
- Nothing lints the shell that ships: `scripts/deploy.sh`, `scripts/audit_lock.sh`, `scripts/build_wheelhouse.sh`, `deploy/nodesource.sh`.
- At shellcheck 0.11.0 the tree has one finding, `deploy/nodesource.sh:50` SC2064. It is intentional.
- All three CI jobs run on `ubuntu-latest`, which is now 26.04 (run 41003391205). co-processor is 24.04. `ci.yml`'s Redis comment already says "pin runs-on".

**Approach.**
- **`scripts/shellcheck.sh [--staged]`** is broker's selector:
  - it takes every tracked `*.sh` and `.githooks/*`;
  - it skips `skills-vendor/`, `.skills/` and symlinks;
  - it runs `exec uv run --frozen --no-config --only-group lint shellcheck -- …`.
  - **`--no-config`, unlike broker** (correction 1 on #81): `[tool.uv] find-links` is read even under `--only-group`, and a clone with no `.wheelhouse` fails. #79's sync uses the same stand-in.
- **`.githooks/pre-commit`:**
  - runs `scripts/shellcheck.sh --staged`;
  - runs `ruff check` and `ruff format --check` over staged `*.py`/`*.pyi`, with `--force-exclude`. There is no Markdown here: ruff has no `extend-include` (correction 3);
  - opt-in per clone with `git config core.hooksPath .githooks`.
- **`pyproject.toml`:**
  - `lint = ["ruff>=0.16.8,<0.17", "shellcheck-py>=0.11.0.1,<0.12"]`;
  - `dev` gains `{ include-group = "lint" }` and loses `ruff`.
  - The lock moves by `uv lock` alone: `git diff uv.lock` is `shellcheck-py`, plus the group edges.
  - The release's `uv sync --no-dev` installs neither tool. Verified with `uv export --frozen --no-dev`, which lists neither.
- **`ci.yml`:**
  - a `shellcheck` step in `lint`, after `uv sync`. It is not a job, so `CI_JOBS` is unchanged.
  - `runs-on: ubuntu-24.04` on `lint`, `test` and `audit.yml`'s `audit` (operator, 2026-10-30).
- **`deploy/nodesource.sh:50`:** line 48's reason becomes the directive, on the line before. A trailing directive doesn't suppress (correction 2).
- **Docs:**
  - `docs/DEPLOYMENT.md` § Shell lint, after § CI pins and Dependabot: the selector, the opt-in, the version, how to bump;
  - AGENTS.md's CI row and Common Commands.

**Tests (red first).**
- `tests/test_shellcheck.py` (new; broker's `test_shellcheck_gate.py`, cut to what we run, under a fake `uv`):
  - the lock: `lint` carries shellcheck-py and ruff, `dev` includes `lint`, and ruff sits in `lint` alone. The wheel is a hashed manylinux x86_64. The doc names the locked version;
  - the selector: it takes every own script and no upstream one, and the tree is clean;
  - the hook: a planted finding fails the commit, a clean script commits, and staged Python is ruff-checked and format-checked. Upstream scripts are skipped. A deletion lints nothing;
  - the wiring: a step of `lint`, after `uv sync`. Both callers spell `--frozen --no-config --only-group lint`. The opt-in is documented.
- `tests/test_ci.py`:
  - every job in `ci.yml` and `audit.yml` runs on `ubuntu-24.04`;
  - on co-processor, `/etc/os-release` is that version (skipped off the node, by hostname).

**Deploy.** Yes: `pyproject.toml`, `uv.lock` and `deploy/nodesource.sh` are `RUNTIME_*`. The release's contents don't change, but the drift check reads paths.

**Verified after the merge.** CI is green on the merge's push run, on 24.04. Then `scripts/deploy.sh`, the verdict line read live, and drift `ok`.

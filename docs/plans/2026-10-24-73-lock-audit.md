# Report-only `uv.lock` audit

## Problem

Nothing reads `uv.lock` against OSV. #71's 12 advisories surfaced only because archiver's coordinator ran `uv audit` by hand. Disclosures arrive without commits, so a push-only check is not enough either.

## Approach

Port broker's `audit.yml` + `scripts/audit_lock.sh` + guard test, adapted:

1. `.github/workflows/audit.yml`: push to `main`, PRs to `main`, weekly `schedule`, `workflow_dispatch`. `permissions: contents: read`, no `id-token`, no secret. Action pins equal `ci.yml`'s (tag majors; this repo has no SHA-pin convention yet). One job, `timeout-minutes: 5`, `run: bash scripts/audit_lock.sh`.
2. `scripts/audit_lock.sh`: `cd` to the checkout (or warn "did not run"), `uv audit --frozen --preview-features audit-command` (retry flagless on uv < 0.11.19's "Unknown feature flag"), **always exit 0**:
   - exit 1 → `::warning title=uv.lock advisories::` + job summary;
   - any other non-zero → `::warning title=uv audit did not run::`, never clean;
   - OSV text echoed between `::stop-commands::<random>` and its resume token.
   - **Processor's routing** in the warning and the summary, linking DEPLOYMENT.md § Extraction dependencies: an extraction-stack finding is a re-lock + `LOCAL_GENERATION` bump; any other is a re-lock + a `constraint-dependencies` floor (`tests/test_lock_floors.py`).
3. `tests/test_lock_audit.py` (flat layout): fake `uv` on `PATH`; pins every exit, the retry, the warnings, the summary, the stop-commands fence, the routing link, the workflow's triggers/permissions/no-secret/no-`continue-on-error`, and that it stays out of the deploy gate.

**Gate decision: a separate workflow.** `scripts/deploy.sh` reads only `ci.yml`'s push run, so `audit.yml`'s run never counts. A test pins both: `deploy.sh` asks `actions/workflows/ci.yml/runs`, and `ci.yml` has no audit job.

Docs: DEPLOYMENT.md § The CI gate (the audit is outside it), a short `## The lock audit` section; AGENTS.md's CI row.

Not runtime (`processor.drift.RUNTIME_*`): no deploy.

## Check

`uv audit --frozen` on `a23970b`'s lock: 12 found; on `e963107` (after #71): 0 [measured locally, uv 0.13.5]. Script exits 0 either way.

## Tradeoffs

- Report-only means a finding can sit unread. A red gate would turn `main` red on someone else's disclosure date and, if in `ci.yml`, block every deploy. The weekly warning is the nudge.
- Dev-group packages are audited too (no `--no-dev`), as broker does: a dev finding is cheap to re-lock, and silence is worse.
- No Dependabot: it can't sync the private wheelhouse.

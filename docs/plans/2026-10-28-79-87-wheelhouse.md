# The wheelhouse: a locked sync, pinned digests

Two PRs, #79 first. Ports of broker#113 (`1ea9ed0`) and broker#125 (`241bcd5..7360463`).

## #79: the sync's deps come from uv.lock

**Problem.** `uv run --no-project --no-config --with 'google-cloud-storage>=2,<4'` resolves the sync's env afresh from PyPI on every run, outside `uv.lock` and the audit. In CI that happens with the `co-pypi-reader` credential set. Sites: `ci.yml:58` and `:122`, `scripts/sync_wheelhouse.py:13`, `AGENTS.md:32`.

**Approach.**
- A `wheelhouse` dependency group, `google-cloud-storage>=3,<4` (the project's own spec). `uv lock` adds only the group.
- Every site runs `uv run --frozen --no-config --only-group wheelhouse python scripts/sync_wheelhouse.py`.
- **`--no-config` stays.** It replaces broker's tracked `.wheelhouse/.gitkeep`, which we don't have: `.wheelhouse` is git-ignored and a worktree links it. Measured on a fresh clone with a cold cache and uv 0.13.5:
  - without it, uv fails on the missing find-links directory;
  - with it, uv installs 21 packages (`google-cloud-storage` 3.15.1 from the lock), and neither co-core nor the project.
- The sync's summary line names the `google-cloud-storage` version it ran on, so CI's log shows the locked version.

**Tests (red first).**
- `tests/test_ci.py`: every tracked file outside `tests/` that spells a `uv run` of the sync spells exactly `--frozen --no-config --only-group wheelhouse`. The CI file, the docstring and `AGENTS.md` must all be among them. This replaces the two `--no-config`-only tests.
- The group exists in `pyproject.toml` and `uv.lock`, and names nothing from the wheelhouse.
- `tests/test_sync_wheelhouse.py` (new): the summary line names the version.

**Deploy.** `pyproject.toml` and `uv.lock` are `RUNTIME_FILES` (`drift.py:64`), so this is a deploy. The release's `uv sync --no-dev` installs no groups, so the release's venv is unchanged.

## #87: a locked wheelhouse file is held to a committed sha256

**Problem.** `uv.lock` locks co-core by `path =` with no hash. uv 0.13.5 records none for a find-links file and drops a hand-added one at the next lock. The sync skips any same-size file (`sync_wheelhouse.py:54`), and `deploy.sh:303` copies `.wheelhouse` into the release unchecked. A same-size substitution is installed and deployed.

**Approach (broker#125's shape).**
- `[tool.processor.wheelhouse-sha256]` in `pyproject.toml`, one `"file" = "hex"` line per file `uv.lock` names from the wheelhouse. The three 0.38.0 wheels; no sdists are locked.
- **Sync:**
  - still mirrors the whole prefix;
  - a locked file is skipped only when its sha256 matches its pin, and is otherwise fetched again;
  - a download that misses its pin is refused, and the planted copy is left as found;
  - a locked file with no pin, a pin that isn't a sha256, or a locked file the bucket doesn't list fails the sync.
- **`deploy.sh`, in `build_release`:**
  - copies only the files `uv.lock` names into the release, not the whole `.wheelhouse`;
  - holds each copy to the release's own pin before `uv sync`;
  - a mismatch, a missing pin or a missing file is refused with `say` before `die`, before the switch;
  - a pass is journaled through `say`, naming the files.
- **The pin test** (`tests/test_pin.py`) holds the digest table's file names to the pinned version: a bump that moves the pin and not the digests is red.
- **Docs:** `docs/DEPLOYMENT.md` § Bumping co-core gains the digest step, with a re-check that a local build matches the bucket's (reproducibility rests on the build backend's timestamp handling). AGENTS.md's co-core paragraph points to it.

**The 0.38.0 comparison.** This host's local builds (`build_wheelhouse.sh`; no ADC here) are the pins' candidates. CI's from-empty sync is the bucket's side. The sync refuses a mismatch, so a green CI `test` on the PR is the comparison. If it's red on a digest, stop and ask.

**Tests (red first).**
- `tests/test_sync_wheelhouse.py`, against a fake GCS client:
  - a planted same-size wheel is kept by the old sync (red), and fetched again by the new one;
  - a mismatching download is refused;
  - a planted copy is left as found when the refetch misses too;
  - an unlisted locked file, a missing pin and a malformed pin each fail the sync;
  - an unlocked same-size file is still skipped;
  - the real table equals the lock's files, in the form `deploy.sh` reads;
  - a synced wheelhouse here matches the pins.
- `tests/test_deploy.py`:
  - a planted same-size wheel is installed by today's deploy (red), and refused by the new one, journaled, with nothing switched;
  - a pass is journaled;
  - only locked files reach the release;
  - a missing pin and a missing file are refused.

**Accepted limits.**
- A reused release isn't re-checked (a rollback to a kept build). Builds from before #87 were never checked.
- A rebuild of a pre-#87 build is refused, since it has no table.
- The pin-time gap (cannobserv#591) is out of scope.
